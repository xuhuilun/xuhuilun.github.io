## 摘要

大模型服务的主要瓶颈已从算力转向内存：自回归解码阶段，每条请求的 KV 缓存随序列长度线性增长，而传统连续内存分配造成的碎片化浪费高达 60%–80%，直接限制了可并发处理的请求数（批大小），压低了 GPU 吞吐。本文深入剖析 vLLM 提出的 **PagedAttention**——借鉴操作系统虚拟内存的分页思想，将 KV 缓存按固定大小的块管理，通过逻辑块到物理块的映射表实现近乎零浪费的显存利用，并天然支持共享前缀（并行采样）。论文实验表明，vLLM 相比 FasterTransformer 可实现 **2–4 倍**吞吐提升，同时保持相同延迟水平。本文从问题背景、核心算法、系统调度到实验评估与后续演进，给出系统性解读。

## 引言

2023 年之后，大语言模型（LLM）从离线训练快速走向在线服务：聊天、代码补全、agent 工具调用都要求毫秒级响应与高并发。然而 LLM 的在线服务与经典深度学习推理（如 CNN 分类）有本质差异——**自回归生成**的每条请求都包含一个逐 token 递进的解码循环，请求之间长度差异巨大，内存需求动态且不可预知。这让"内存管理"成为服务系统的第一等公民。

在 FasterTransformer、HuggingFace Transformers 等主流框架中，KV 缓存按请求预分配一整块连续显存。这种朴素策略在长短请求混合的真实负载下会产生严重碎片：既有多分配的内部碎片，也有请求间无法互用的外部碎片。vLLM（Kwon et al., SOSP 2023）给出的答案是：**像操作系统管理物理内存一样管理显存**。本文按学术报告结构，从问题、机制、系统、实验、展望五个层面展开。

## 背景与问题

### KV 缓存的内存增长

标准多头注意力中，KV 缓存由每层每头的 K、V 矩阵构成。对 FP16 精度，序列长度为 $S$ 时的缓存大小为：

$$
M_{\text{KV}} = 2 \times L \times H \times d_{\text{head}} \times S \times 2 \ \text{bytes}
$$

以 LLaMA-13B（40 层、40 头、$d_{\text{head}}=128$）为例，每 token 约 0.8 MB，生成长度 2K 的回复就需要约 **1.6 GB** 显存，且随请求数线性累加。解码阶段每个 token 的算术强度（FLOPs/byte）极低，是典型的 **memory-bound** 负载——GPU 算力再强，也喂不饱内存带宽。

### 连续分配的三重浪费

传统实现（如 `past_key_values`）为每条请求预先分配一段**连续**显存，长度按该请求可能的最大长度预留：

- **内部碎片**：请求实际只生成了 200 token，却按 2048 token 预留，其余 90% 空间闲置且无法被其他请求使用；
- **外部碎片**：不同请求的连续区块之间留下无法合并的小空隙，即使总空闲量充足，也可能放不下一条新请求；
- **预留失败**：预分配时机无法预知实际需求，请求中途 OOM 只能整批失败重来。

设请求平均长度 $\bar{S}$、最大长度 $S_{\max}$，则平均内存利用率仅为 $\bar{S}/S_{\max}$。真实负载中该值常低至 20%–40%——论文报告朴素方案的内存浪费达 **60%–80%**。低利用率直接导致批大小受限，而批大小恰恰决定了解码阶段的吞吐。

| 维度 | 连续分配（HuggingFace/FT） | PagedAttention（vLLM） |
|------|------|------|
| 分配单位 | 整条请求的连续显存 | 固定大小块（16 token） |
| 预留策略 | 按最大长度预分配 | 按需分配，动态增长 |
| 碎片/浪费 | 60%–80% | &lt;4%（块级） |
| 请求间复用 | 不可能 | 共享前缀物理块 |
| 批量上限 | 受最长请求制约 | 仅受总显存制约 |

## PagedAttention 算法详解

### 分页与块表映射

PagedAttention 将每条请求的 KV 缓存划分为固定大小的**逻辑块**（默认每块 16 个 token），通过**块表**（block table）映射到 GPU 显存中的**物理块**——与虚拟内存的页表如出一辙：

```text
逻辑块序列（请求视角）          块表（逻辑 -> 物理）           物理显存（全局共享）
┌──────────┬──────────┐      ┌───────────────┐        ┌─────┬─────┬─────┬─────┐
│ Block 0  │ Block 1  │      │  Block 0 -> 7 │        │  7  │  9  │  3  │  1  │
│ (token   │ (token   │ ───► │  Block 1 -> 9 │ ────►  ├─────┼─────┼─────┼─────┤
│  0-15)   │  16-31)  │      │  Block 2 -> 3 │        │  4  │  8  │  5  │  2  │
└──────────┴──────────┘      └───────────────┘        └─────┴─────┴─────┴─────┘
  逻辑上连续、按需增长            每请求一张表             物理上离散、全局按块分配
```

逻辑上连续的块在物理上可以离散存放，因此：

1. **按需分配**：请求开始时只分配一个块，随生成逐块追加，绝不预占；
2. **近零浪费**：除最后一个不完整块外，所有物理块 100% 被使用，块级浪费最坏情况为 $1/16 \approx 6.25\%$，典型负载约 4%；
3. **全局共享**：物理块由所有请求共用同一"显存池"，彻底消除请求间的外部碎片。

### 块级注意力计算

Attention 计算按块进行。对第 $i$ 个逻辑块，先计算缩放点积得分 $s_i$，再归一化为注意力权重 $\alpha_i$：

$$
\begin{aligned}
s_i &= \frac{Q K_i^T}{\sqrt{d_k}}, \\
\alpha_i &= \operatorname{softmax}(s)_i
= \frac{\exp(s_i)}{\sum_{j=1}^{n} \exp(s_j)}
\end{aligned}
$$

PagedAttention kernel 逐个读取块表中的物理块参与计算；对于最后一块（可能不满 16 个 token），通过掩码忽略无效位置，保证结果与不缓存时完全一致。该 kernel 与 FlashAttention 的 tiling 思路兼容，可将分页读取与访存优化结合。

### 共享上下文：并行采样与前缀复用

分页的另一个红利是**共享物理块**。并行采样（beam 搜索/多次采样）时，多条输出序列共享同一 prompt 前缀——它们可以**指向同一组物理块**，仅在分叉后写入新块；若后续需要改写共享块，则触发 **copy-on-write** 复制。这使得前缀缓存的显存开销从"请求数 × 前缀长度"降为"唯一前缀 × 1"。

## 系统设计与调度

vLLM 将 PagedAttention 嵌入完整的服务系统，核心是三层设计：

- **块管理器（Block Manager）**：维护全局物理块池的分配/释放/引用计数，支持 fork（共享）与 copy-on-write；
- **PagedAttention Kernel**：按块表执行注意力，是计算核心；
- **调度器（Scheduler）**：实现**连续批处理**（continuous batching）。

### 迭代级连续批处理

传统框架按"请求级"批处理：一个批次等所有请求生成完毕才切换下一批，GPU 在批次尾部出现大量空闲。vLLM 改为**迭代级（iteration-level）调度**：每一轮解码都重新计算"本轮该调度哪些请求"，新请求可随时插入当前批次，完成的请求即时退出。配合分页显存，批大小只受总显存约束，GPU 利用率因此大幅提升。

### 抢占（Preemption）

当显存不足时，调度器需要抢占某些请求。vLLM 支持两种模式：**交换（swap）**——将请求的部分物理块拷到 CPU 内存，显存释放后再拷回；**重算（recompute）**——丢弃部分块，恢复时重算。为降低开销，每次迭代最多只抢占一个请求，使抢占成本与其他请求的并行计算重叠。

## 实验评估

论文在 OPT-13B/70B、LLaMA-2 等模型上，对比 FasterTransformer 与 Orca，报告了以下关键数据：

| 指标 | 结果 | 解读 |
|------|------|------|
| 吞吐提升 | 相比 FasterTransformer **2–4 倍**；相比 Orca 平均约 **2.7 倍** | 收益来自显存节省 → 更大批处理 → 解码阶段吞吐近似正比于批大小 |
| 并行采样 | 吞吐最高提升约 **3.8 倍** | 共享前缀使多条序列的显存开销≈1 条，直接放大有效批量 |
| 显存浪费 | 从 60%–80% 降至 **&lt;4%** | 分页 + 按需分配消除内外碎片，只剩末块级浪费 |
| 延迟 | 与基线持平或更优 | 分页只改变存储布局，不增加计算量 |

**解读**：吞吐收益并非来自更快的 kernel，而是"内存效率 → 批大小 → 吞吐"的传导链——这正是把问题定义为"内存管理问题"而非"计算问题"的价值所在。值得注意，收益在**长序列、长短混合、高并发**负载下最显著；在序列极短的单请求场景，收益有限。

## 讨论与展望

**局限性**：其一，块粒度是权衡——块越小浪费越少，但块表与 kernel 开销越大（默认 16 是经验折中）；其二，抢占（尤其 swap）在显存紧张时引入额外 I/O 开销；其三，分页 kernel 的实现复杂度高，需与 FlashAttention 等优化深度耦合。

**后续方向**：分页思想已成为推理系统的事实标准并持续演进——自动前缀缓存（APC）将共享推广到任意公共前缀；chunked prefill 与预填充/解码解耦进一步平滑调度；KV 量化、CPU/异构内存 offload 与分页结合，把"内存墙"继续后推；而 MLA、GQA 等架构侧压缩则从源头削减每 token 的缓存量，与系统侧分页形成互补。
