# Favicon Design

## 背景

站点首页已经采用蓝、红、黄、绿四色矩阵作为主标志，但现有 favicon 仍是包含字母 X、纸飞机、城市和海浪的蓝色插画。旧图标在 16px 标签页尺寸下细节难以辨认，也与当前首页品牌语言不一致。

本次设计将 favicon 统一为首页现有的原生四色矩阵。设计优先保证小尺寸识别，不额外叠加字母、论文或 AI 图形。

## 设计目标

- favicon 与首页主标志保持同一视觉语言。
- 在 16px、32px 等常见浏览器尺寸下清晰可辨。
- 同时适用于浅色和深色浏览器界面。
- 覆盖 Next.js 页面及仓库中的旧静态页面，不改变现有引用路径。
- 保留可维护的矢量源文件，所有位图从同一母版生成。

## 非目标

- 不重新设计首页主标志或站点完整品牌系统。
- 不增加字母 L、LLM、书本、论文或 AI 等额外图形。
- 不修改页面布局、导航或站点配色。
- 不引入新的项目运行时或构建依赖。

## 视觉规范

### 画布与结构

- 基准画布：512x512，透明背景。
- 外边距：四边各 32px，占画布的 6.25%。
- 色块：四个 192x192 的等大圆角矩形，排列为 2x2 矩阵。
- 色块间距：横向和纵向均为 64px。
- 圆角半径：54px，约为单个色块边长的 28%。
- 不使用外框、底板、描边、阴影、渐变或文字。

上述数值满足 `32 + 192 + 64 + 192 + 32 = 512`，可按目标尺寸等比缩放。16px 输出对应约 1px 外边距、2px 色块间距和 6px 色块边长，能保持清晰分隔。

### 颜色与位置

| 位置 | 颜色 | 十六进制 |
| --- | --- | --- |
| 左上 | 蓝色 | `#4285F4` |
| 右上 | 红色 | `#EA4335` |
| 左下 | 黄色 | `#FBBC05` |
| 右下 | 绿色 | `#34A853` |

颜色及排列与首页 `GoogleMark` 组件保持一致。透明背景让图标自然适配浏览器浅色和深色标签页。

## 资产设计

### 矢量源文件

新增 `public/img/favicon.svg`，作为 favicon 的唯一设计母版。SVG 使用 512x512 `viewBox` 和四个明确填色的圆角矩形，不依赖字体、滤镜、外链资源或 CSS。

### 输出文件

替换以下现有资产，文件路径保持不变：

- `public/img/favicon.png`
- `public/img/favicon-16x16.png`
- `public/img/favicon-32x32.png`
- `public/img/favicon-48x48.png`
- `public/img/favicon-64x64.png`
- `public/img/favicon-96x96.png`
- `public/img/favicon-128x128.png`
- `public/img/favicon-192x192.png`
- `public/img/favicon-512x512.png`
- `public/img/favicon.ico`

`favicon.png` 使用 512x512 输出，供仍直接引用该文件的旧静态页面使用。`favicon.ico` 内含 16x16、32x32 和 48x48 三档图像。所有 PNG 使用 RGBA 模式和透明背景。

### 页面集成

Next.js 元数据和旧静态页面已经引用上述路径，因此本次不修改 `app/layout.tsx` 或静态 HTML。替换同路径资产后，全站自动使用新 favicon。

## 生成流程

1. 按视觉规范创建 512x512 SVG 母版。
2. 从同一几何参数生成 512px RGBA 位图。
3. 使用高质量缩放依次生成各目标 PNG 尺寸。
4. 从母版生成包含 16px、32px、48px 的 ICO 文件。
5. 对所有输出执行尺寸、格式、透明通道和颜色检查。

资产生成仅使用开发环境已有的图像工具，不写入项目依赖。生成失败或任一规格不匹配时停止流程，不提交部分资产。

## 验收标准

### 自动检查

- SVG 可解析，画布、四个色块的坐标、圆角和颜色符合规范。
- 每个 PNG 的像素尺寸与文件名一致，模式为 RGBA。
- ICO 包含 16x16、32x32、48x48 三档。
- 所有现有 favicon 引用均能解析到仓库内文件。
- `npm run typecheck` 通过。
- `npm run build` 通过。

### 视觉检查

- 生成浅色和深色背景的对比图。
- 在 16px、32px 和 128px 下检查外边距、间距及圆角一致性。
- 16px 下四个色块仍相互分离，未出现颜色串联或透明边缘异常。
- 浅色和深色标签页中均无需额外描边即可辨认。

## 风险与控制

- 浏览器可能缓存旧 favicon。部署后需要通过硬刷新或无痕窗口验证，缓存不作为资产错误处理。
- 16px 栅格化会产生亚像素取整差异。最终以 16px 实际输出为准，并通过视觉对比确认四块均衡。
- 原生四色矩阵造型较通用，辨识度主要来自固定配色和站内一致使用。本次明确接受该取舍，不增加额外符号。

## 完成条件

全部资产按规范生成，自动检查与视觉检查通过，功能分支提交并推送；随后合并到主分支并推送远端。
